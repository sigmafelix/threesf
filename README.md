# threesf — 3D vector measures without PostGIS

A dependency-free C++17 library implementing the PostGIS/SFCGAL 3D function
family over **Simple Features Z geometries**, with full **WKT/EWKT and WKB/EWKB**
I/O, a C ABI for FFI, and wrappers for **Python** (ctypes + numpy, shapely
interop) and **R** (`.Call`, compiled in-package, `sf` interop).

```
threesf/
├── core/include/threesf/threesf.hpp     header-only core (types, measures, distances, tessellation, extrusion)
├── core/include/threesf/io.hpp        WKT/EWKT + WKB/EWKB reader/writer (all SF Z types, SFCGAL SOLID)
├── core/include/threesf/threesf_c.h     C ABI: opaque handles (WKT/WKB in) + legacy flat-array encoding
├── core/src/threesf_c.cpp             C ABI implementation
├── tests/test_threesf.cpp        analytic ground-truth tests (cube, hollow cube, L-prism, holed polygon…)
├── tests/test_io.cpp           WKT/WKB round-trips for every type + PostGIS hex-EWKB fixtures
├── python/                     pip-installable package (`pip install ./python`), pytest suite
├── r/threesf/                    R package with testthat suite and Rd docs (core vendored via `make r-sync`)
├── core/CMakeLists.txt              library + tests + install/export targets
├── .github/workflows/ci.yml    C++ / Python / R matrix, wheel builds on tags
└── core/Makefile                    make test | make python | make r-sync  (dev convenience)
```

## Simple Features compatibility

| Type (Z)                    | WKT | WKB | Notes |
|-----------------------------|-----|-----|-------|
| POINT, MULTIPOINT           | ✓   | ✓   | `POINT Z EMPTY` ↔ WKB NaN-NaN (PostGIS convention) |
| LINESTRING, MULTILINESTRING | ✓   | ✓   | |
| POLYGON, MULTIPOLYGON       | ✓   | ✓   | holes supported |
| TRIANGLE                    | ✓   | ✓   | ISO type 17 |
| POLYHEDRALSURFACE           | ✓   | ✓   | ISO type 15 |
| TIN                         | ✓   | ✓   | ISO type 16; written as TIN, not collapsed to a surface |
| GEOMETRYCOLLECTION          | ✓   | ✓   | arbitrarily nested |
| SOLID, MULTISOLID           | ✓   | ✓   | SFCGAL extension (WKB types 101/102) |

Reader tolerances, so that anything PostGIS, sf, shapely, GEOS or GDAL emit is accepted:

- Dimension markers: `POINT Z (…)`, `POINTZ(…)`, `POINT ZM (…)`, `POINT M (…)`, and
  marker-less PostGIS form `POINT(1 2 3)`; case-insensitive.
- 2D input gets `z = 0` (this is exactly what PostGIS's 3D functions do); M is parsed
  and discarded.
- `SRID=n;` EWKT prefix; EWKB flag bits (`0x80000000` Z, `0x40000000` M, `0x20000000`
  SRID); ISO offsets (1000/2000/3000); both byte orders.
- `EMPTY` at any nesting level; `MULTIPOINT (1 2 3, 4 5 6)` and `MULTIPOINT ((1 2 3), (4 5 6))`.

Writers emit ISO style (`POLYGON Z ((…))`, WKB type + 1000) by default, or EWKT/EWKB
with SRID on request. Coordinates use shortest-round-trip formatting, so WKT → WKB →
WKT is bit-exact.

`tests/test_io.cpp` includes byte-level fixtures generated by PostGIS (`ST_AsEWKB`,
`ST_AsBinary`) to guarantee interoperability rather than mere self-consistency.

## Algorithms

- **Area**: Newell's method — |Σ cross-products| / 2 per ring, holes subtracted. Exact for planar
  polygons of any shape (concave, holed) and equals the projected area on the best-fit plane for
  slightly non-planar ones; `area_tessellated` gives the true triangulated surface area instead.
- **Volume**: divergence theorem over the tessellated boundary, V = ⅙ Σ a·(b×c). Sign encodes
  orientation (`signed_volume`), which is what `force_outward`/`make_solid` use. Inner shells
  are subtracted.
- **Tessellation**: ear clipping in an orthonormal plane basis derived from the Newell normal,
  with holes merged through nearest mutually visible bridges. Output winding follows the input ring.
- **Distance**: geometries are decomposed to point/segment/triangle primitives; pairwise minima use
  Ericson's closed-form segment–segment and point–triangle routines (*Real-Time Collision
  Detection*, §5.1). Points strictly inside a solid get distance 0 via ray casting.
  Complexity is O(|A|·|B|) primitives — fine for building-scale objects; add a BVH before
  running city-scale joins.
- **is_closed / is_solid**: edge-manifold check — every undirected edge shared by exactly two
  patches; *solid* additionally requires each edge traversed once in each direction (consistent
  orientation).

## C ABI

The handle API is the primary entry point:

```c
threesf_handle* h = threesf_read_wkt("SOLID Z ((((0 0 0, …))))");   /* or threesf_read_wkb / threesf_read_hexwkb */
double v = threesf_h_volume(h);
char* wkt = threesf_h_wkt(threesf_h_tessellate(h), /*ewkt=*/0);   /* "TIN Z (((…)))" */
if (!h) puts(threesf_last_error());
threesf_free(wkt); threesf_h_free(h);
```

A zero-copy flat-array encoding (`threesf_geom`) remains for callers that already
hold coordinate buffers; interleaved xyz with `n+1`-style `*_starts` offsets:

| type | coords | ring_starts | patch_starts | shell_starts |
|------|--------|-------------|--------------|--------------|
| 0 POINT(S) | points | – | – | – |
| 1 LINESTRING(S) | vertices | part starts | – | – |
| 2 POLYGON(S) | vertices | ring starts | polygon → rings | – |
| 3 SURFACE / TIN | vertices | ring starts | patch → rings | – |
| 4 SOLID | vertices | ring starts | patch → rings | shell → patches (0 = outer) |

and builds wheels with cibuildwheel on version tags.

```python
import threesf as g3
poly  = g3.read_wkt("POLYGON Z ((0 2 0, 10 2 0, 10 2 10, 0 2 10, 0 2 0), (4 2 4, 4 2 6, 6 2 6, 6 2 4, 4 2 4))")
```


## 3D construction and validation

```python
a = g3.st_extrude(g3.polygon([(0, 0), (2, 0), (2, 2), (0, 2)]), 0, 0, 2)
b = g3.st_extrude(g3.polygon([(1, 1), (3, 1), (3, 3), (1, 3)]), 0, 0, 2)
i = g3.st_3dintersection(a, b)  # volume 2
u = g3.st_3dunion(a, b)         # volume 14
hull = g3.st_3dconvexhull(u)
d = g3.st_3ddifference(a, b)    # volume 6
assert not g3.st_selfintersects(d)
```

- **Convex hull**: incremental 3D hull of every input vertex. The result is a
  `SOLID`, or `POLYGON`, `LINESTRING`, `POINT`, or empty geometry collection for
  lower-dimensional inputs. Duplicates and interior points are handled.
- **Booleans**: BSP clipping of triangulated, closed, consistently oriented
  solids or polyhedral surfaces. Cavities and disconnected components are
  reconstructed as `SOLID` / `MULTISOLID`. These are **regularized volume
  operations**: an intersection consisting only of a face, edge, or point is
  empty. Open surfaces and nonempty point/line/polygon operands are rejected.
  Components within an operand must have disjoint interiors. Non-manifold
  results, such as a union sharing only an edge, are rejected.
- **Validation**: crossing rings, crossing faces, coplanar overlaps, duplicate
  triangles, and intersections beyond shared vertices/edges are detected.
  Booleans validate inputs and outputs; splitting vertices are welded and
  inserted into neighboring edges to preserve a watertight mesh. Tessellation,
  extrusion, and solid construction refuse self-intersections. Ear clipping
  fails explicitly when triangulation cannot complete safely.
- **Warnings**: C/Python/R readers warn about self-intersecting input. Python
  emits `RuntimeWarning`; R emits a warning; the C API exposes the last
  operation's thread-local `threesf_last_warning()`. C++ constructive functions
  warn on stderr by default, or through `threesf::warning_handler`. A convex
  hull may safely use a self-intersecting input's vertices after warning.
  Rejected operations raise a C++ exception / Python `ValueError` / R error;
  the C ABI returns NULL, NaN, or -1 and sets `threesf_last_error()`.
- **Tolerance and SRID**: the new functions accept a finite positive `tol`
  (default `1e-9`) in coordinate units. Construction translates/scales to a
  local frame, with a machine-precision tolerance floor. Features below this
  tolerance may collapse or be rejected. Hulls preserve SRID; Boolean operands
  must have identical SRIDs. No coordinate transformation is performed.

The BSP approach is described in [Evan Wallace's CSG algorithm notes](https://github.com/evanw/csg.js/).

## Plotting in Python and R

Both bindings draw points, curves, polygons with holes, TINs, surfaces, solids
(including cavity shells), and nested collections in XYZ coordinates. Pass one
geometry or a list to compare objects with separate colors. Empty inputs produce
an empty scene. Plotting uses the core tessellation and preserves its validation
warnings/errors. There is no CRS transformation.

Python uses optional Matplotlib (static) and Plotly (interactive):

```sh
pip install './python[plot]'
```

```python
ax = g3.plot(prism, color="steelblue", alpha=0.8)
ax.figure.savefig("prism.png", dpi=200)       # or PDF/SVG
fig = prism.plot(interactive=True)
fig.show()                                 # rotate, zoom and inspect
fig.write_html("prism.html")                # includes Plotly for offline viewing
# Multiple objects; hide mesh edges while retaining curves:
g3.plot([prism, hull], color=["steelblue", "orange"], edges=False)
```

Static calls return a Matplotlib 3D axes; pass `ax=` to overlay another geometry.
Interactive calls return a Plotly Figure. Neither calls `show()` automatically.
`color`, `alpha`, `edges`, `linewidth`, `point_size`, and `title` control appearance;
returned axes/figures support further backend-specific customization. Importing
threesf does not import or require either plotting backend.

R static plotting uses base graphics; interactive plotting optionally uses Plotly:

```r
plot(prism, col = "steelblue", alpha = 0.8)
png("prism.png", width = 900, height = 700)   # pdf() also works
plot(prism)
dev.off()

install.packages("plotly")                  # once, for interactive plotting
widget <- g3_plot(prism, interactive = TRUE)
widget                                     # viewer/browser or an R Markdown document
htmlwidgets::saveWidget(widget, "prism.html", selfcontained = FALSE)
# Keep prism_files/ with the HTML when sharing this export.
g3_plot(list(prism, hull), col = c("steelblue", "orange"), edges = FALSE)
```

`plot.threesf` delegates to `g3_plot`; static mode invisibly returns the `persp`
projection matrix, and interactive mode returns a Plotly htmlwidget. Static
viewing angles use `theta` and `phi`. Face opacity (`alpha`), line width (`lwd`),
marker size (`point_size`), and title (`main`) are configurable.

Static plots use approximate depth sorting, so intersecting or transparent
surfaces may exhibit drawing artifacts. Interactive views allow rotating and
zooming for inspection. Mesh edges include all stored patch boundaries; use
`edges=False` (Python) or `edges=FALSE` (R) to hide triangulation lines.

## Caveats

- Predicates use doubles, not exact arithmetic. Numerically unresolved or
  invalid meshes can be rejected; no automatic self-intersection repair is
  attempted. This is not a full SFCGAL mixed-dimensional Boolean kernel.
- Self-intersection checks and vertex welding are quadratic; distance queries
  also have no spatial index. The implementation targets small/building-scale
  geometries rather than city-scale joins.
- Existing distance routines do not subtract cavity interiors during containment
  tests and can miss segment/triangle interior crossings. These limitations do
  not affect the new Boolean kernel, which uses separate intersection tests.
- SOLID/MULTISOLID WKB type codes (101/102) follow SFCGAL; PostGIS itself has no
  SOLID storage type, so exchange solids as `POLYHEDRALSURFACE Z` +
  `st_makesolid()` when talking to it.

Run `make -C core clean` to remove CMake/Make builds, Python native builds, and
R object/shared-library artifacts. `make -C core r-sync` refreshes the vendored
R headers and C ABI, including `constructive.hpp`.
